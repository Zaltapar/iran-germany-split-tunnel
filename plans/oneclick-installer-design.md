# One-Click Installer Design (read-only)

Scope: design only. No files modified, no host access, no Arvan calls, no
commit/push. Goal: one-click install on Iran + Germany reusing `splitterctl`,
with the ONLY manual step being the copy of a single generated pairing secret.
Dashboard installs on **Germany only**, over TLS on a **custom random path**,
reusing the existing Arvan/CDN cert, without interfering with Xray Reality on
`:443`. Test on a fresh disposable VPS before production.

---

## 1. Existing machinery (file:line evidence)

### 1.1 `splitterctl install` — the deployment engine
- `cmd/splitterctl/main.go:317-345` `installCommand`: `requireLinux` gate →
  `installRequestFromEnv(role)` → `deploy.NewLinuxAdapter(request,
  systemd.OSExecutor{}, firewall.OSExecutor{})` → `controller.ApplyRequest`.
- `internal/deploy/adapter.go:117-174`: transaction = preflight → validate →
  backup → activate → transition → health → **commit manifest last**. A crash
  leaves `journal.json`; `splitterctl recover` reverts it (`main.go:737-803`).
- State under `/etc/split-tunnel` (`internal/systemd/systemd.go:72`):
  `state.json` (`internal/deploy/state.go`), `revisions/`, `journal.json`, and
  D4 env files `<role>.env` (0600 root:root) written by
  `systemd.WriteEnvFile` (`internal/systemd/envfile.go:97-183`). Root converges
  to `0750 root:split-tunnel` (`systemd.go:88`).
- **Iran** provisions `iran-splitter` (+ `iran-origin` Caddy if caddy/tlsOrigin)
  — `internal/deploy/systemd_plan.go:21-68`.
- **Germany** provisions `xray-germany` (ExecStart
  `/opt/split-tunnel/xray/current/xray run -config
  /etc/split-tunnel/xray-germany.json`, `internal/systemd/render.go:207-209`) +
  `germany-splitter`. Reality keypair generated by pinned Xray
  (`internal/xray/keygen.go:67-139`), config rendered
  (`internal/xray/realityconfig.go:209`), activated behind `xray run -test`
  with a `0600 .prev` backup (`internal/xray/activate.go:93-200`).
- Env contract consumed (`main.go:12-56, 818-835`): `SPLIT_*`
  (`internal/config/config.go:48-96`), `SPLITTERCTL_SPLITTER_BIN/_VERSION`,
  Germany `XRAY_VERSION/REALITY_*`, Iran `ORIGIN_MODE/UPLOAD_DOMAIN/ORIGIN_PORT/
  ACME_*/CDN_*`, `FIREWALL_BACKEND/FW_ALLOW/FW_DENY`.
- `config set/upgrade/rollback/uninstall` re-derive the request from the **same
  environment** (`main.go:476-721`) — manifest stores fingerprints, not secrets.

> **Decision: the installer CALLS `splitterctl install` + `splitterctl pair`
> and does NOT re-implement any host mutation.** The legacy `install.sh` is
> explicitly DEPRECATED/non-production (`install.sh:33-37`). The new installer
> only bootstraps (fetch/verify source, install Go, build 3 binaries, export the
> env) then delegates. No second transaction engine.

### 1.2 Pairing flow
- `internal/pairing/pairing.go:277-333` **Blob A** (Iran→Germany): `secret` +
  `uploadDomain`. `pairing.go:349-400` **Blob B** (Germany→Iran): public
  Reality params + down host/port (**public only**; the Reality private key
  never leaves Germany, `pairing.go:10-14`).
- `cmd/splitterctl/main.go:1189-1291`: `pair generate` (Iran,
  `SPLITTERCTL_SECRET_FILE`+`UPLOAD_DOMAIN` → Blob A to stdout and optional
  `SPLITTERCTL_PAIR_BLOB_OUT` 0600, `main.go:1335-1405` no-follow atomic);
  `pair apply` (Germany, `SPLITTERCTL_PAIR_BLOB_FILE` → Blob A in, Blob B out,
  idempotent via `internal/deploy/pair.go:65-101`); `pair finalize` (Iran, Blob
  B in).
- Only SHA-256 **fingerprints** are persisted (`pair.go:123-126`); raw blobs and
  the secret never enter state/logs/errors.

**Handoff:** the only secret-bearing artifact is **Blob A (Iran → Germany)**;
Blob B is public. So the single manual copy is **Iran → Germany** (Blob A).

### 1.3 Xray / Reality
- **Germany fully automatic**: `splitterctl install germany` pins/verifies/
  downloads Xray (`internal/xray/install.go:153-300`), keygen, render, activate,
  wire the unit. SNI/shortId/UUID from env (`main.go:888-913`), auto-generable
  via `pairing.GenerateShortID/GenerateUUID` (`pairing.go:250-269`).
- **Iran open question.** `config/iran-xray-config.json` is the operator-managed
  3x-ui template; `upgrade --xray` is Germany-only (`main.go:610-617`).

> **Decision (Iran, one-secret):** default = **project-managed Xray consumer**
> on Iran: reuse `internal/xray/install.go` (role-agnostic binary install:
> download → SHA-256 verify → stage → `xray version` smoke → `xray run -test`)
> to place pinned Xray at `/opt/split-tunnel/xray/<ver>/` + a new
> `internal/xray/consumerconfig.go` rendering a deterministic consumer config:
> VLESS+Reality inbound `0.0.0.0:443` with **Blob B's** public params, a
> `to-splitter` socks outbound to `127.0.0.1:<SOCKS_PORT>`, and a routing rule.
> New `xray-consumer.service` unit. Iran's `SPLIT_DOWN_CARRIER_ADDR` = the
> loopback target. Validation reuses `pairing.ValidSNI/ValidUUID/ValidShortID`
> (single source of truth, `pairing.go:211-227`).
> Fallback opt-in `--iran-xray external`: keep the operator's 3x-ui Xray and
> print a paste-in snippet (reuse `install.sh:991-1008`).

### 1.4 CDN / origin
- `internal/origin` modes `caddy|cdn|none` (`origin.go:76-80`). Live Arvan
  topology = `cdn plainOrigin` port 80, `arvan.ctoplace.ir`
  (`IMPLEMENTATION_STATUS.md:332-378`; `ops-scratch/plainhttp-migration/*`;
  `final-suite/socks5-and-production-verify.log:45-54`).
- No on-host Arvan cert today: caddy mode uses Let's Encrypt in Caddy storage
  (`origin/cdn.go:417-421`); mode B's public cert is held by the **Arvan edge**.
- `SPLIT_WS_LISTEN` (default `127.0.0.1:9001`) is fronted by the origin
  provider (`main.go:1029-1033`).

> **Decision (origin):** installer takes explicit origin params (domain/mode/
> port/cdn-security), defaulting to the live Arvan plain-HTTP topology. Fresh
> VPS without Arvan → `caddy` (ACME) or `none`/`ws://` direct-orig
> mode fallback so a test host with no CDN still converges.

## 2. One-secret flow (the only manual step)

Direction: **Iran generates, Germany consumes.** Blob A carries the secret, so
it must travel Iran → Germany. Blob B is public and travels Germany → Iran.

To keep it to **one** secret the user copies, the installer collapses the two
blobs into a single handoff artifact:

1. **Iran (bootstrap, fully automatic):**
   - `splitterctl install iran` (sets `SPLIT_WS_LISTEN`, origin params, secret
     env). The installer generates `SPLIT_SECRET` via
     `pairing.GenerateTunnelSecret` (`pairing.go:236-248`), writes it to
     `/etc/split-tunnel/secrets/secret` (0600), and exports
     `SPLITTERCTL_SECRET_FILE` + `SPLITTERCTL_UPLOAD_DOMAIN`.
   - `splitterctl pair generate` → emits **Blob A** (carries the secret +
     upload domain). Installer captures it to a 0600 file
     `/root/.pairing/blob-a` (via `SPLITTERCTL_PAIR_BLOB_OUT`).
   - **Iran also installs the project-managed Xray consumer** but holds back
     `SPLIT_DOWN_CARRIER_ADDR`/finalization until it has Blob B.
   - The user is told: **copy this one file from Iran to Germany**
     (`/root/.pairing/blob-a`).
2. **Germany (bootstrap, fully automatic):**
   - `splitterctl install germany` (Xray pinned + Reality keygen + config +
     units).
   - User pastes the **one** blob (Blob A) into a 0600 file
     `/root/.pairing/blob-a`; `SPLITTERCTL_PAIR_BLOB_FILE` +
     `SPLITTERCTL_PAIR_DOWN_HOST` exported.
   - `splitterctl pair apply` → consumes Blob A (secret now on Germany), emits
     **Blob B** to `/root/.pairing/blob-b`.
   - **User copies Blob B back to Iran** (public, but completes the exchange)
     and `splitterctl pair finalize` on Iran.

> The *secret* is the one thing the user manually moves (Iran→Germany as Blob A).
> Blob B is public and could in principle be auto-returned over the tunnel, but
> v1 has no control channel, so it is a second (public) copy. The requirement is
> met: **the ONLY secret ever carried is Blob A.** Both copies use 0600 files +
> `SPLITTERCTL_PAIR_BLOB_OUT` (no-follow atomic, `main.go:1335-1405`), never
> stdout-logged. The installer logs only fingerprints
> (`main.go:1281`), never the blob bytes.

SOCKS credentials, metrics, host addresses: **generated/derived, never
prompted.** SOCKS user/pass (if enabled) via `pairing.GenerateTunnelSecret`-style
randomness; host addresses auto-detected (`detectGermanyHostFromInterfaces`,
`main.go:1125-1156`); Reality public key derived from the installed private key
on Germany (`internal/deploy/pair.go:85-90`), never generated on the wire.

## 3. Dashboard on Germany (tunneldash)

Existing facts:
- `cmd/tunneldash/main.go` is a **local-only** tool: binds 127.0.0.1:8080,
  read-only, fixture data, no SSH (its own doc banner, `docs/tunneldash.md:1-15`).
- `internal/dashboard/server.go:101-146` **refuses non-loopback binds** — a hard
  gate that must be relaxed for a server-hosted TLS build.
- `internal/dashboard/config.go:36-87` `Validate`: `ListenAddr` defaults to
  `127.0.0.1:8080`; `ReadOnly` default true; servers may use `ssh` source.
- `internal/dashboard/ssh_config.go:215-250` `ValidateSSHConfig`: **strict,
  pinned** SSH — `StrictHostKeyChecking=yes` hard-coded, pinned `knownHosts`
  required, `BatchMode=yes`, `PasswordAuthentication=no`, `-F /dev/null`,
  `ProxyCommand/Jump=none`, fixed remote-command allowlist, unprivileged user.
- `config/tunneldash-ssh-example.json:7-54` shows the exact two-server SSH shape
  (Germany local `sourceType` can be `http`/`ssh` to 127.0.0.1; Iran remote via
  pinned SSH).
- `internal/dashboard/auth.go:43-72` `BearerTokenAuthenticator` already exists
  (empty token = off); `internal/dashboard/mutator.go` + nil mutator keep
  mutations 403 by default.

> **Decision (dashboard-on-Germany):**
> - **TLS build:** add a `dashboard.TLSConfig{CertFile, KeyFile, BasePath}` to
>   the schema and a `NewTLSServer` path that serves over a **dedicated TLS
>   port** (NOT 443 — 443 is Xray Reality). Default `127.0.0.1` bind is lifted
>   to `0.0.0.0:<port>` **only when** a `BasePath` (random 32-hex) is set AND TLS
>   is enabled AND a Bearer admin token is set; otherwise the existing
>   loopback gate stays. This keeps the WARP-style lockout risk in check
>   (the surface is a random path under a random-ish high port, not 443).
> - **Custom path:** `BasePath` e.g. `/a3f9...c2/` (32-hex, generated by
>   `openssl rand -hex 16`). All routes (`/api/v1/...`, UI) mount under it
>   (`internal/dashboard/ui.go` / `server.go` Router). The path is the
>   *secret* of access; combined with the Bearer token for defense in depth.
> - **Cert/key source:** reuse the **Arvan/CDN cert** the operator already has.
>   The installer copies the operator-supplied `--cert`/`--key` PEMs to
>   `/etc/split-tunnel/dashboard/tls/{cert.pem,key.pem}` with `0640
>   root:split-tunnel` (group-readable so the non-root `tunneldash` unit reads
>   its own key — mirrors the `StateDirMode 0750` pattern,
>   `internal/systemd/systemd.go:81-88`). The key is never echoed; the unit
>   passes the paths via `EnvironmentFile=/etc/split-tunnel/dashboard.env`
>   (0600 root:root, D4 pattern, `internal/systemd/envfile.go`).
> - **systemd unit** `tunneldash.service`: `User=split-tunnel`,
>   `Group=split-tunnel`, `ExecStart=/opt/split-tunnel/tunneldash
>   -config /etc/split-tunnel/dashboard/config.json`,
>   `EnvironmentFile=/etc/split-tunnel/dashboard.env`, `Restart=on-failure`,
>   hardening (`NoNewPrivileges=true`, `PrivateTmp=true`,
>   `ProtectSystem=full`, `ProtectHome=true`, `CapabilityBoundingSet=`,
>   `ReadWritePaths=/var/log/split-tunnel`), `Wants=network-online.target`.
>   Follows the checked-in hardening style
>   (`systemd/germany-splitter.service:18-24`).
> - **SSH collector (Germany local + Iran remote):** config
>   `/etc/split-tunnel/dashboard/config.json` uses `sourceType=ssh` for Iran
>   with a **dedicated unprivileged `monitor`** account, an identity file
>   `/etc/split-tunnel/dashboard/ssh/monitor_key` (0600) and a **pinned
>   known_hosts** `/etc/split-tunnel/dashboard/ssh/pinned_kh` (0640) containing
>   only Iran's host key — mirroring `config/tunneldash-ssh-example.json:16-30`.
>   Germany's own metrics can be read via the `ssh`/`http` loopback source
>   (no remote dial). `readOnly=true` + `allowMutations=false` on every server
>   (default, `config.go:40-42`), so no mutation path exists.
> - **Admin token (if mutations are ever enabled later):** installer generates
>   a 32-hex token, stores it in `dashboard.env` (`DASHBOARD_ADMIN_TOKEN`,
>   0600), and constructs a `BearerTokenAuthenticator` (`auth.go:43-72`). Until
>   then the token is unset and access = TLS + random path + loopback only.
>
> **Why a separate TLS port + random path (not `:443`):** Xray Reality owns
> `0.0.0.0:443` on Germany (`internal/xray/realityconfig.go:70-73`). tunneldash
> must be reachable by a browser, so it runs on its **own high port**
> (e.g. `8443`) with TLS using the Arvan/CDN cert, mounted under the random
> `BasePath`. This never collides with Reality and is firewalled by default.

## 4. Installer script design (`install-oneclick.sh`)

Single top-level script, `set -euo pipefail`, no `curl|bash` of remote code,
all quoting `"$var"`, all remote fetches checksummed.

**Phases:**
1. `preflight`: root check (`id -u`), OS/distro detect (Debian/Ubuntu via
   `/etc/os-release`), systemd present, arch, disk, **clone or tarball**.
2. `fetch_source`: `git clone` repo to `/opt/split-tunnel-src`; on any failure
   (no git / no network / Iran GitHub-reachability) fall back to a **tarball**:
   operator-provided `--tarball /path/repo.tar.gz` **or**
   `https://github.com/Zaltapar/iran-germany-split-tunnel/archive/refs/tags/<v>.tar.gz`
   with a pinned `SHA256` (the user verifies Iran's GitHub/apt reachability
   separately; the tarball is the guaranteed fallback). Verify the source
   `go.mod` module path and, for the tarball, the published SHA-256 before
   building.
3. `toolchain`: install Go if `go` missing or < required (`go.mod` is `go 1.21`),
   official tarball, arch-matched, `/usr/local/go` + `profile.d` (reuses the
   `install.sh:790-833` pattern but pinned, checksummed).
4. `build`: `go build` **all three** binaries — `./cmd/iran-splitter`,
   `./cmd/germany-splitter`, `./cmd/splitterctl`, and `./cmd/tunneldash` —
   into `/opt/split-tunnel/`. (Iran host builds iran-splitter + splitterctl +
   tunneldash-not-needed; Germany builds germany-splitter + splitterctl +
   tunneldash. Build per role to keep cross-builds simple: `CGO_ENABLED=0`,
   `GOOS=linux`.)
5. `configure`: write the role env (SPLIT_*) that `splitterctl` will read.
   The script does **not** invent config; it collects/derives values and
   exports the documented env vars (§1.1 table) + generates `SPLIT_SECRET`.
6. `delegate`: `splitterctl install <role>` (the ONLY mutation entrypoint),
   then the role's `splitterctl pair …` step (§2). **On any non-zero exit,
   stop and point the operator at `splitterctl recover`** (journal-driven
   rollback, `main.go:737-803`) — the script adds no host of its own.
7. `dashboard` (Germany only): build/install `tunneldash`, copy the
   operator-supplied Arvan/CDN cert to `/etc/split-tunnel/dashboard/tls/`
   (0640 root:split-tunnel), generate `config.json` + `dashboard.env`, write
   the hardened `tunneldash.service`, enable it.
8. `verify`: `splitterctl doctor` + `status`; `systemctl is-active` on each
   unit; curl the loopback metrics; (Germany) `openssl s_client` to the
   dashboard TLS port.
9. `report`: print the one-secret handoff command, dashboard URL
   (`https://<germany-host>:8443/<basepath>/`), firewall hints, and `--help`-
   style next steps. Masked secret by default.

**Flags / interface:**
- `install-oneclick.sh iran|germany [--non-interactive]`
- Iran: `--cdn-domain`, `--origin-mode [cdn|caddy|none]`,
  `--origin-port`, `--cdn-security [plainOrigin|tlsOrigin]`,
  `--iran-xray [managed|external]` (default managed), `--socks-user/--socks-pass`
  (optional RFC 1929).
- Germany: `--reality-sni`, `--down-listen` (default `:9002`),
  `--dashboard` (default on), `--dashboard-port` (default `8443`),
  `--dashboard-path` (default auto 32-hex), `--cert PEM` `--key PEM`
  (Arvan/CDN cert; required when `--dashboard`).
- Common: `--secret <hex64>` (or auto-gen), `--yes`, `--dry-run`, `--uninstall`,
  `--tarball PATH`, `--help`, `--show-secret`.

**Safety properties:** `set -euo pipefail`; `trap` to leave source tree
intact; every downloaded byte checksummed (Go, tarball, and the pinned
Xray/Caddy are already verified inside the Go packages
`internal/xray/install.go:194-214` + `internal/origin` fetch/checksum); no
secret ever printed unless `--show-secret`; firewall changes only through
`SPLITTERCTL_FIREWALL_BACKEND` (project-marked rules, `internal/firewall`,
never a shell flush); rollback is **always** `splitterctl recover` / `rollback
--to` (never ad-hoc). Idempotent: re-running `splitterctl install` on a
converged host reports "already converged" (`main.go:337-344`).

## 5. Security, firewall, ports

- **No WARP-style lockout** (the 2026-10-07 incident,
  `final-suite/WARP-INCIDENT-2026-10-07.md`): the installer touches **no**
  global egress routing/`ip rule`, no WARP/VPN, no DNS override. The only
  egress the tunnel dials is the operator's existing up-carrier URL; the
  firewall package only adds **project-marked** allow/deny rules
  (`internal/firewall/firewall.go:18` `Marker`, `143-160` Apply/Remove never
  flush). The dashboard adds one **isolated** high port behind a random path —
  it can be dropped without touching the data path.
- **Ports to open (recommended):**
  - Iran: `443/tcp` (Xray consumer Reality inbound), `80/tcp` only if
    plain-Origin CDN mode B (Arvan edge→origin), SSH `22` (for the dashboard
    monitor account + key rotation). SOCKS `10900` stays **loopback only**
    (Iran Xray dials it, never exposed).
  - Germany: `443/tcp` (Xray Reality), `8443/tcp` (dashboard TLS, firewalled
    to the operator's IP by default via `SPLITTERCTL_FW_DENY`/a dedicated
    allow rule), SSH `22`. Down-carrier `:9002` is reached **inside** the
    Reality tunnel, not a separate public port.
- **TLS cert perms:** `/etc/split-tunnel/dashboard/tls/key.pem` 0640
  root:split-tunnel, `cert.pem` 0640; the `tunneldash` unit runs as
  `split-tunnel` (non-root) and reads its own key group-readable — mirroring
  the `0750` state-root convention (`internal/systemd/systemd.go:81-88`).
- **Secrets in env/systemd:** secret lives only in 0600 root:root env files
  (D4, `internal/systemd/envfile.go:1-18`), never in unit `Environment=`.
- **SSH keys:** dedicated unprivileged `monitor` user + pinned
  `known_hosts` (0640) + 0600 identity; `StrictHostKeyChecking=yes`
  (`internal/dashboard/ssh_config.go:240-246`), `BatchMode=yes`,
  `PasswordAuthentication=no`, `-F /dev/null`, `ProxyCommand/Jump=none`.
- **Dashboard hardening:** random `BasePath` (32-hex) + TLS + optional Bearer
  token; `CSP: default-src 'self'`, `X-Frame-Options: DENY`,
  `X-Content-Type-Options: nosniff`; no CORS (already unconditional off,
  `internal/dashboard/types.go:149-150`); POST bodies capped 64 KiB
  (`server.go:49,75`); path IDs charset-checked (`docs/tunneldash.md:33`).
  Rate limiting: reuse the poll interval; add a token-bucket in the reverse
  proxy layer if the browser is exposed beyond the operator's IP.

## 6. Disposable-VPS test plan

Two fresh VPS (or one, run roles sequentially) as **Iran** and **Germany**
testboxes; **no** Arvan, no production hosts.

**Matrix:**
| # | Step | Verify |
|---|---|---|
| 1 | Iran: `install-oneclick.sh iran --non-interactive --iran-xray managed --origin-mode none --yes` | `splitterctl doctor` clean; `iran-splitter`+`xray-consumer` active; `state.json` role=iran, generation set |
| 2 | Iran: `splitterctl pair generate` → blob-a (0600) | stdout only fingerprints; file exists 0600 |
| 3 | **Copy blob-a Iran→Germany** (the one manual step) | byte-identical on both ends |
| 4 | Germany: `install-oneclick.sh germany --non-interactive --dashboard --cert … --key … --yes` | `xray-germany`+`germany-splitter`+`tunneldash` active; `splitterctl doctor` clean |
| 5 | Germany: `SPLITTERCTL_PAIR_BLOB_FILE=blob-a splitterctl pair apply` → blob-b | blob-b 0600; idempotent on re-run |
| 6 | **Copy blob-b Germany→Iran**; `splitterctl pair finalize` | state `pairing.state=finalized` |
| 7 | End-to-end: run a SOCKS5 client on Iran → `curl -x socks5h://127.0.0.1:10900 https://example.com` | 200 through the tunnel |
| 8 | Dashboard: `openssl s_client -connect germany:8443` + browser to `https://germany:8443/<basepath>/` | UI renders, overview 200, Iran shown `fresh` via pinned SSH |
| 9 | Drift/heal: tamper a unit file, re-run `splitterctl install germany` | drift-heal commits, converges |
| 10 | Crash rollback: `kill -9` mid-`config set`, `splitterctl recover` | journal reverted, mutations unblocked |
| 11 | Rollback: `splitterctl rollback --to <prior-state-id>` | prior revision restored |
| 12 | Uninstall: `splitterctl uninstall` (+`--purge` optional) | units removed, state clean |
| 13 | Idempotence: re-run every install | "already converged" |

**Teardown:** `splitterctl uninstall --purge` on both; `rm -rf
/opt/split-tunnel-src /opt/split-tunnel`; `systemctl disable --now` any
leftover units; delete `/etc/split-tunnel`; drop the VPS.

**Success = production-ready:** steps 1–8 all green, `state.json` pairing
`finalized` on Iran + `a-applied` on Germany, SOCKS5 egress works, dashboard
TLS reachable only at the random path, and rollback/recover (9–12) all
converge. No production endpoint, Arvan API, or non-loopback secret ever
touched.

## 7. Risks & open decisions
- **Dashboard public surface:** opening a TLS port on Germany is new attack
  surface. Mitigated by random path + IP firewall + Bearer token. *Open:* is
  a high port acceptable, or must it stay loopback + SSH-tunnel-only? (Design
  chose the port + random path per the "TLS and a custom path" requirement.)
- **Iran Xray: managed vs 3x-ui.** *Open:* default managed (design) leaves a
  second Xray on hosts that already run 3x-ui on `:443`. If a target Iran box
  has 3x-ui on 443, use `--iran-xray external` + a non-443 consumer port.
  *Open:* confirm the disposable-VPS Iran has no pre-existing 443 occupant.
- **Cert source:** the design assumes the operator supplies the Arvan/CDN
  cert PEMs at install (`--cert/--key`). *Open:* confirm the exact on-host
  path the operator's Arvan edge cert/key live at (today the caddy-mode cert
  is auto-issued in Caddy storage; plain-HTTP mode B has no on-host cert).
- **Second (public) copy:** strictly the *secret* is one (Blob A). Blob B
  (public) still moves Germany→Iran because v1 has no control channel.
  *Open:* acceptable, or must the installer auto-return Blob B over the newly
  established tunnel (needs a control-channel feature not yet in the codebase)?
- **Go on Iran (GitHub/apt reachability):** user verifies separately; the
  tarball + pinned-Go checksum covers the no-network case.
- **Firewall backend auto-detect ambiguity:** `ufw`+`nftables` together
  fails closed (`internal/firewall/firewall.go:100-118`) — testboxes must
  have a single active manager.
